# maintain guides

Use the docs index for navigation. Product rules belong in the Product Guide, code topology and failure paths in the System Design Guide, and operating steps in a runbook. For meaningful architecture changes trace a real request and draw the decisions, persistence and failure branches in Mermaid. Cite source files and distinguish current from proposed behavior. Capture consequential tradeoffs in a short dated decision. When superseded, move obsolete guidance to docs/history, record its replacement, fix incoming links, and keep the current guide readable. A refactor needs a doc change only when it invalidates an explanation.
