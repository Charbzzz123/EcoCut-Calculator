# check change

Map each changed behavior to a check. Docs → links and examples. Setup → changed command. Business logic → focused Vitest or Jest test. API or storage → exercise the real local API against temporary data. Browser workflow or layout → run the relevant TypeScript spec under e2e using the repo Playwright config. For example, `npx playwright test e2e/linked-job.spec.ts` checks the linked-job journey. Inspect `playwright.config.ts` and e2e/support.ts before reproducing provider flows. Use synthetic records and mocks. Use the wider suite for shared navigation, cross-cutting changes or release verification. Report command, result, scope and gaps. A mocked read or send cannot establish live delivery.
