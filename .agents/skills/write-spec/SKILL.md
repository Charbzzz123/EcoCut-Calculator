# write spec

Read the current guide and affected code. Identify the operator, trigger, desired outcome, existing behavior, exclusions and one unresolved decision if it blocks work. Use a success and failure example when meaningful. Mark facts observed in code separately from proposed changes. Small features can live in the story body. Place cross-story product rules in the Product Guide. For read-only communications specify which transports must receive zero deliveries and which history reads must keep working.
